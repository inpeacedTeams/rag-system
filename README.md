# Источник: чат с вашими документами

Рабочее веб-приложение RAG: загрузка PDF/TXT, импорт текста страницы сайта, векторный поиск и ответы с источниками. Backend не возвращает заранее подготовленные ответы и не использует фиктивные эмбеддинги: в рабочем режиме выполняются настоящие запросы к Kiro и Qdrant, а эмбеддинги вычисляются локальной ONNX-моделью FastEmbed.

## Быстрый запуск

Нужны Docker с Compose v2 и API-ключ Kiro с доступом к `qwen/qwen3.8-omni-flash:free`. Отдельный ключ OpenAI не нужен. На первую загрузку модели эмбеддингов нужен интернет; её файлы сохраняются в Docker volume `embedding_cache`.

```bash
git clone https://github.com/inpeacedTeams/rag-system.git
cd rag-system
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

В `.env` заполните `KIRO_API_KEY` своим ключом Kiro, а `SESSION_SECRET` строкой из последней команды. Ключ не вставляйте в чат, frontend или GitHub. Затем:

```bash
docker compose up --build -d
```

Откройте **http://localhost:8000**. Загрузите файл или вставьте ссылку, дождитесь окончания индексации и задайте вопрос. Раскройте карточку источника под ответом, чтобы увидеть дословную цитату, имя файла, страницу PDF и номер чанка.

```bash
# Посмотреть логи
docker compose logs -f app

# Остановить, сохранив базу
docker compose down

# Обновить после изменения .env
docker compose up --build -d --force-recreate app

# Удалить ВСЮ базу всех сессий, необратимо
docker compose down -v
```

Кнопка «Очистить базу знаний» удаляет только материалы текущей браузерной сессии. Можно удалять отдельные документы. При удалении локальная история чата сбрасывается, чтобы не оставлять ссылки на удалённые источники.

## Стек и устройство

**FastAPI + Python 3.12** обслуживает API и статический интерфейс на HTML/CSS/JavaScript. Сборка frontend и Node.js для запуска не нужны. **Qdrant** является настоящей векторной базой с cosine-поиском и постоянным Docker volume. **Kiro** отвечает через `https://api.xkiro.com/v1/chat/completions`, модель `qwen/qwen3.8-omni-flash:free`. **FastEmbed 0.7.4** вычисляет настоящие локальные эмбеддинги на CPU моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, размер 384. Модель многоязычная, включая русский. API-ключ остаётся на сервере.

При загрузке PDF извлекается текст каждой страницы отдельно. Текст нормализуется и разбивается на фрагменты до 1400 символов с перекрытием до 220 символов. Чанк всегда сохраняет страницу, номер, имя и ID документа. Перед индексацией фрагменты дополнительно проверяются реальным токенизатором модели: длинные фрагменты делятся на участки до 480 токенов с сохранением дословного текста и страницы. Это предотвращает молчаливое обрезание при эмбеддинге. Эмбеддинги вычисляются локально пакетами по 16 фрагментов, затем все фрагменты документа отправляются в Qdrant одним подтверждаемым запросом. Исходный бинарный файл не хранится: в базе остаются извлечённый текст, эмбеддинги и метаданные.

При вопросе создаётся его эмбеддинг и выбирается до восьми фрагментов только из базы текущей сессии. Результаты ниже `MIN_RELEVANCE_SCORE` отбрасываются. Модель получает только вопрос и эти фрагменты, возвращая структурированные утверждения с точными цитатами. Backend отвергает несуществующий источник или цитату, отсутствующую в тексте. Второй запрос к модели отдельно проверяет, следуют ли все утверждения из цитат и отвечают ли они на вопрос. Любой отрицательный результат проверки даёт ответ:

> В загруженных документах нет этой информации

Ошибки сети, ключа, баланса или базы показываются как ошибки сервиса, а не маскируются под отсутствие информации. Вопрос к пустой базе обрабатывается без вызова Kiro и локальной модели.

**Важно:** RAG и дополнительная модель-проверяющий существенно уменьшают риск галлюцинаций, но не дают математической гарантии правильности. Наличие цитаты проверяется детерминированно, логическая обоснованность проверяется моделью. Важные выводы необходимо сверять с цитатами. Возможны ложные отказы, особенно при вопросах, требующих анализа всего большого документа: используется top-k retrieval, а не полный контекст всей базы.

## Интерфейс

Адаптивный интерфейс на русском языке включает drag-and-drop и выбор нескольких файлов с последовательной обработкой, импорт URL, список документов, индикатор обработки, чат, раскрываемые цитаты, удаление отдельных документов и подтверждение очистки базы. Ответы и названия вставляются через `textContent`, не через HTML. История чата хранится только в DOM текущей вкладки, не в базе. Каждый вопрос рассматривается самостоятельно: вместо «а когда это было?» укажите предмет вопроса явно.

## Лимиты и ограничения

Поддерживаются текстовые PDF и TXT в UTF-8. Лимиты: 20 МБ на файл, 300 страниц на PDF, 1000 чанков на документ и 30 документов на сессию. Для PDF-сканов без текстового слоя нужен предварительный OCR. Зашифрованные PDF не принимаются. Это явные ошибки, а не молчаливая загрузка пустой базы.

Импортируется **одна публичная страница**, не весь сайт. Страницы, которые требуют входа, CAPTCHA или исполнения JavaScript для появления контента, не поддерживаются. HTML очищается от скриптов, навигации и служебных блоков. Разрешены HTTP/HTTPS и порты 80/443; локальные, приватные и служебные IP запрещены. DNS проверяется, соединение закрепляется за проверенным IP, каждый redirect проверяется заново. Размер ответа ограничен 5 МБ, число redirects ограничено.

Первый импорт может занять больше времени из-за скачивания модели эмбеддингов. GPU не требуется. Контейнеру приложения выделен лимит 1,5 ГБ RAM, желательно иметь не менее 4 ГБ RAM на сервере для Docker и обоих сервисов.

База изолирована подписанной HttpOnly cookie, `SameSite=Strict`. Все операции с векторной базой фильтруются по серверному ID сессии. Это **не учётные записи**: другой браузер увидит новую базу, очистка cookie лишит доступа к старой, а украденная cookie даёт доступ к соответствующей базе. Старые бесхозные данные автоматически не удаляются. Для команды или публичного SaaS нужны отдельная авторизация, квоты по аккаунтам и политика хранения.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `KIRO_API_KEY` | Обязательный ключ Kiro, только на сервере |
| `SESSION_SECRET` | Обязательный случайный секрет длиной не менее 32 символов |
| `CHAT_BASE_URL` | По умолчанию `https://api.xkiro.com/v1` |
| `CHAT_MODEL` | По умолчанию `qwen/qwen3.8-omni-flash:free` |
| `CHAT_RESPONSE_FORMAT` | `prompt` по умолчанию; опционально `json_object` или `json_schema` при поддержке провайдером |
| `EMBEDDING_MODEL` | Локальная модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| `EMBEDDING_DIMENSIONS` | 384, должно соответствовать локальной модели |
| `EMBEDDING_CACHE_DIR` | `/models` в контейнере, подключён постоянный volume |
| `EMBEDDING_THREADS` | Число CPU-потоков ONNX, по умолчанию 2 |
| `MIN_RELEVANCE_SCORE` | Порог cosine score, по умолчанию 0.35; не вероятность правильности |
| `QDRANT_URL` | Адрес Qdrant; Compose задаёт `http://qdrant:6333` |
| `QDRANT_COLLECTION` | Новая коллекция `documents_kiro_minilm_v1` |
| `QDRANT_API_KEY` | Необязательный ключ при подключении к внешнему защищённому Qdrant |
| `COOKIE_SECURE` | `true` при публикации через HTTPS, `false` для локального HTTP |

### Миграция с первой версии OpenAI

Если уже создавали `.env`, обновите его по `.env.example`: задайте `KIRO_API_KEY`, `CHAT_BASE_URL=https://api.xkiro.com/v1`, `CHAT_MODEL=qwen/qwen3.8-omni-flash:free`, `CHAT_RESPONSE_FORMAT=prompt`, локальную `EMBEDDING_MODEL`, размер `EMBEDDING_DIMENSIONS=384` и **новую** `QDRANT_COLLECTION=documents_kiro_minilm_v1`. Не оставляйте старые значения модели и размера. Сохраните прежний `SESSION_SECRET`.

После `docker compose up --build -d` документы нужно загрузить заново. Старые 1536-мерные OpenAI-векторы несовместимы с новой 384-мерной моделью и остаются в старой коллекции до отдельного удаления администратором. Приложение их не использует. Нельзя смешивать разные модели даже при одинаковом размере вектора. Текущий адаптер токенизации намеренно поддерживает только указанную MiniLM-модель; простая подмена имени другой моделью отвергается.

`CHAT_RESPONSE_FORMAT=prompt` отправляет стандартные `model`, `messages`, `max_tokens`, без требования `response_format`/`json_schema` или OpenAI-специфичного `max_completion_tokens`. JSON-схема описывается в системном сообщении. Ответ строго разбирается на сервере; поддерживается цельный JSON или один JSON code fence. Некорректный JSON, отказ модели и обрезанный ответ показываются как ошибки сервиса. Неверные цитаты или отрицательная проверка обоснованности приводят к отказу отвечать. Дополнительные reasoning-поля от провайдера не используются, проверяется только `message.content`.

Для совместимости принимается старый `OPENAI_BASE_URL`, но `CHAT_BASE_URL` имеет приоритет. Старый `OPENAI_API_KEY` используется только при явно выбранном не-Kiro адресе; при адресе `api.xkiro.com` необходим `KIRO_API_KEY`, чтобы случайно не отправить ключ другого провайдера. Не используйте ключ OpenAI для Kiro: у провайдеров разные ключи. Можно явно настроить другой OpenAI-совместимый chat API, однако эмбеддинги всё равно останутся локальными.

**Передача данных:** документы для эмбеддингов обрабатываются на вашем сервере. Для генерации ответа и проверки в Kiro отправляются вопрос и найденные фрагменты, а не весь документ целиком. Перед загрузкой конфиденциальных материалов проверьте политику Kiro. Суффикс `:free` не означает отсутствие квот или бессрочную гарантию бесплатности: доступ и лимиты определяет провайдер. Локальные эмбеддинги не требуют оплаты API, но расходуют CPU/RAM вашего сервера. На успешный ответ выполняется до двух запросов к модели Kiro.

## Публикация на сервере

Compose привязывает приложение только к `127.0.0.1:8000`, а Qdrant не открывает порт на хосте. Для доступа из интернета поставьте reverse proxy с TLS перед приложением. Например, при установленном Caddy и настроенном DNS:

```caddyfile
rag.example.com {
    request_body {
        max_size 21MB
    }
    reverse_proxy 127.0.0.1:8000
}
```

Замените домен своим, включите `COOKIE_SECURE=true` и перезапустите приложение. Reverse proxy должен сохранять исходный `Host`. Ограничьте доступ авторизацией на proxy, если сайт не предназначен для всех. По умолчанию приложение содержит только грубый лимит 20 операций в минуту на cookie-сессию и 120 на процесс. Создание новой сессии позволяет обойти индивидуальный лимит; это не защита API-бюджета от публичного злоупотребления.

Приложение работает одним worker. Локальные блокировки сериализуют изменение базы и ответы для каждой сессии (с фиксированными lock stripes), а лимиты находятся в памяти. Горизонтальное масштабирование требует распределённых блокировок и внешнего rate limiter. Контейнер приложения запускается не от root, файловая система read-only, временные файлы находятся в ограниченном tmpfs. Qdrant хранит текст и эмбеддинги на диске, резервные копии и шифрование диска настраиваются на стороне инфраструктуры.

## API

Документация схем доступна по `/api/docs`. Cookie-сессия создаётся при первом запросе. Все изменяющие запросы требуют заголовок `X-Requested-With: DocumentRAG`; CORS для чужих сайтов не включён.

| Метод | Путь | Операция |
| --- | --- | --- |
| GET | `/health` | Готовность процесса |
| GET | `/api/status` | Проверка наличия ключа и лимиты |
| GET | `/api/documents` | Документы текущей сессии |
| POST | `/api/documents/upload` | Multipart, поле `file` |
| POST | `/api/documents/url` | JSON: `{"url":"https://example.org"}` |
| POST | `/api/chat` | JSON: `{"question":"Какой срок оплаты?"}` |
| DELETE | `/api/documents/{document_id}` | Удалить документ своей сессии |
| DELETE | `/api/documents` | Очистить свою базу |

Для запросов из CLI сохраняйте cookie между вызовами:

```bash
curl -c cookies.txt http://localhost:8000/api/status
curl -b cookies.txt -H 'X-Requested-With: DocumentRAG' \
  -F 'file=@document.txt' http://localhost:8000/api/documents/upload
curl -b cookies.txt -H 'X-Requested-With: DocumentRAG' \
  -H 'Content-Type: application/json' \
  -d '{"question":"Какой срок оплаты?"}' http://localhost:8000/api/chat
```

## Тесты

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
node --check app/static/app.js
```

`tests/test_core.py` проверяет разбиение, PDF/TXT, цитаты, отказ при неподтверждённых данных, векторные фильтры, обработку провайдера и защиту URL. `tests/test_api.py` проверяет реальные HTTP-маршруты FastAPI с тестовой подменой только внешних API: загрузку, подпись cookie, CSRF, ограничения, изоляцию сессии, очистку и проверку ответа. `tests/test_embeddings.py` проверяет адаптер локальных эмбеддингов и разбиение по токенам. Тесты не используют платный chat API и не доказывают качество реальной модели Kiro. GitHub Actions запускает оба набора, поднимает настоящий Qdrant и отдельно проверяет запись, поиск, пагинацию и изоляцию удаления, проверяет настоящую локальную модель FastEmbed с загрузкой весов, затем проверяет JavaScript и собирает Docker image. Интеграционный тест Qdrant локально пропускается, если не задан `QDRANT_TEST_URL`; проверка настоящих локальных эмбеддингов пропускается без `RUN_EMBEDDING_INTEGRATION=1`. Для локального запуска вне Docker задайте доступный на запись `EMBEDDING_CACHE_DIR`, например `./model_cache`.

### Ручная проверка с настоящими сервисами

Создайте TXT с текстом «Срок оплаты по договору составляет десять рабочих дней.». Загрузите его и спросите «Какой срок оплаты по договору?». Проверьте цитату и номер чанка. Затем спросите «Какой курс доллара сегодня?»: ожидается отказ. Загрузите текстовый PDF и проверьте номер страницы. Откройте другой браузер: его база должна быть пустой. Удалите документы кнопкой очистки и убедитесь, что база пуста после обновления страницы.

Если импорт сайта не работает, убедитесь, что содержимое доступно без JavaScript и авторизации. Если Kiro возвращает 429, проверьте квоты ключа и модели. Если локальная модель не скачивается, проверьте доступ сервера к Hugging Face, права каталога кеша и свободное место. Если меняли размер вектора, используйте новое имя коллекции. Логи доступны через `docker compose logs app qdrant`.
