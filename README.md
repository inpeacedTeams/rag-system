# Источник: чат с документами для Render Free

Рабочий сайт для PDF/TXT и страниц сайта: индексирование, вопросы по загруженным материалам, цитаты с именем файла и страницей, удаление документов и очистка базы. Чат и проверка ответов используют Kiro, данные и разреженные векторы хранятся в Qdrant.

**Текущая версия намеренно использует лёгкий лексический поиск BM25, не нейросетевые эмбеддинги.** Это выбор для Render Free с 512 МБ RAM: никаких моделей FastEmbed/ONNX, Hugging Face, PyTorch или загрузки весов в стандартном образе. Новые API-ключи не нужны, только уже используемые Kiro и Qdrant.

## Запуск на Render Free

Создайте Docker Web Service из `main`. Root Directory оставьте пустым, Dockerfile Path задайте `./Dockerfile`. Compute: Free. Docker Command оставьте пустым, чтобы использовался Dockerfile. Он автоматически читает `PORT`, на Render обычно 10000. Health Check Path: `/health`.

В Environment задайте:

```dotenv
KIRO_API_KEY=YOUR_KIRO_KEY
SESSION_SECRET=YOUR_RANDOM_SECRET
CHAT_BASE_URL=https://api.xkiro.com/v1
CHAT_MODEL=qwen/qwen3.8-omni-flash:free
CHAT_RESPONSE_FORMAT=prompt
QDRANT_URL=https://YOUR_CLUSTER.cloud.qdrant.io
QDRANT_API_KEY=YOUR_QDRANT_KEY
QDRANT_COLLECTION=documents_bm25_v1
MIN_RELEVANCE_SCORE=0
MAX_UPLOAD_MB=5
MAX_PDF_PAGES=100
COOKIE_SECURE=true
PORT=10000
```

Адрес и ключ Qdrant берутся в карточке кластера Qdrant Cloud, не из URL страницы кабинета `cloud.qdrant.io/accounts/...`. У ключа должны быть права на создание коллекции и индекса, чтение, запись и удаление. Для тестирования можно использовать Free кластер, но нужно учитывать актуальные квоты и правила удаления неактивных кластеров провайдера.

Сгенерируйте SESSION_SECRET на своём компьютере:

```bash
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

Ключи и секрет вводите только в Environment, не публикуйте их в чатах или GitHub. Нажмите Manual Deploy → Deploy latest commit. Если Docker Command был задан вручную на порт 8000, очистите поле или используйте:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 10000 --workers 1
```

### Миграция с предыдущей версии

Обязательно установите **QDRANT_COLLECTION=documents_bm25_v1** и **MIN_RELEVANCE_SCORE=0**. Старые коллекции с плотными векторами несовместимы с новым индексом; документы нужно загрузить заново. Приложение не удаляет старую коллекцию автоматически. Сохраните прежний SESSION_SECRET и ключи Kiro/Qdrant.

Удалите старые EMBEDDING_MODEL, EMBEDDING_DIMENSIONS, EMBEDDING_CACHE_DIR и EMBEDDING_THREADS из Environment: они больше не используются. При несовместимой коллекции приложение явно сообщит о необходимости новой коллекции, а не смешает разные векторы. В образе больше нет тяжёлых зависимостей и скачивания Hugging Face.

База Qdrant Cloud сохраняется независимо от перезапусков приложения Render. Render Free может засыпать и имеет ограничения по ресурсам/трафику. Удаление нейросети устраняет её затраты памяти, но не гарантирует обработку произвольных тяжёлых PDF в 512 МБ. По умолчанию ограничены размер файла и страницы, а импорты обрабатываются по одному на процесс.

## Локальный запуск

Нужны Docker с Compose v2 и ключ Kiro. Локальный Compose сам поднимает Qdrant; для него ключ и облачный URL Qdrant не нужны.

```bash
git clone https://github.com/inpeacedTeams/rag-system.git
cd rag-system
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

Заполните KIRO_API_KEY и SESSION_SECRET в `.env`, затем:

```bash
docker compose up --build -d
```

Откройте http://localhost:8000. Логи: `docker compose logs -f app`. `docker compose down` сохраняет базу. `docker compose down -v` необратимо удаляет локальную базу всех сессий. Кнопка очистки сайта удаляет только базу текущей браузерной сессии.

## Как работает поиск

PDF извлекается постранично, TXT принимается в UTF-8. Текст делится на чанки до 1400 символов с перекрытием до 220. Чанк сохраняет дословный текст, имя, ID документа, страницу и номер. Исходные бинарные файлы не хранятся.

Для поиска используются слова и числа, нормализация регистра и «ё», стоп-слова и упрощённая нормализация русских окончаний. Это не полноценный морфологический анализатор. Терминам назначаются стабильные 32-битные идентификаторы с BLAKE2b; редкие коллизии возможны. Код вычисляет частотную и длиновую часть BM25, Qdrant автоматически применяет IDF. Средняя длина чанка является фиксированным параметром BM25_AVG_LENGTH, поэтому это BM25-вариант с приближённой нормализацией, а не точный корпусный BM25. IDF учитывает всю коллекцию, но результаты всегда фильтруются по сессии.

Qdrant использует настоящий sparse-вектор `bm25`, индекс и `modifier=idf`. Разреженные векторы не являются фиктивными нейросетевыми эмбеддингами: это явно лексическое представление. До восьми найденных фрагментов передаются в Kiro. Нейросетевой поиск по синонимам и перефразированным вопросам отсутствует: например, вопрос «Как перечислить деньги?» может не найти текст со словами «Порядок оплаты». Предпочитайте «Какой порядок оплаты?». Формы «оплата», «оплаты», «оплатить» нормализуются к общей основе.

MIN_RELEVANCE_SCORE теперь является порогом BM25 score, не cosine similarity и не вероятностью правильности. Значение 0 сохраняет все найденные совпадения; вопрос без совпадающих терминов даёт отказ без обращения к Kiro.

## Ответы и источники

Модель получает вопрос и найденные фрагменты, без внешних знаний и истории диалога. Структурированный ответ содержит утверждения, ID источника и дословные цитаты. Backend проверяет, что цитата действительно присутствует в указанном фрагменте. Второй запрос Kiro проверяет, следует ли утверждение из цитаты и отвечает ли на вопрос. При отсутствии подтверждения возвращается:

> В загруженных документах нет этой информации

Под ответом отображается файл, страница PDF или номер чанка и раскрываемые цитаты. Для страницы сайта есть ссылка. При ошибке Kiro/Qdrant показывается ошибка сервиса, а не ложное сообщение об отсутствии информации. Некорректные не-JSON ответы инфраструктуры показываются с HTTP-статусом; внутренние ошибки приложения получают код для поиска в Logs.

Проверки снижают риск галлюцинаций, но не дают гарантии корректности. Важные выводы необходимо сверять с цитатами. Отказ означает отсутствие подтверждения среди найденных фрагментов, а не доказанное отсутствие ответа во всех документах. Каждый вопрос независим: явно указывайте предмет вопроса.

## Ограничения и безопасность

По умолчанию 5 МБ на файл, 100 страниц PDF, 1000 чанков на документ, 30 документов на браузерную сессию. Для сканов нужен предварительный OCR. PDF с паролем не принимаются. Импорт URL загружает одну страницу без JavaScript/авторизации, не весь сайт. Доступны публичные HTTP/HTTPS-адреса на 80/443; приватные IP запрещены, DNS закрепляется за проверенным адресом и каждый redirect перепроверяется. Ответ сайта ограничен 5 МБ.

Базы разделены подписанной HttpOnly cookie SameSite=Strict, все запросы Qdrant фильтруются по серверному ID сессии. Это не авторизация аккаунтами: другой браузер создаёт новую базу, удаление cookie лишает доступа к прежней, украденная cookie позволяет получить доступ к соответствующей базе. Бесхозные данные не удаляются автоматически.

Материалы хранятся в Qdrant. Найденные фрагменты и вопросы отправляются в Kiro. Другой провайдер эмбеддингов не используется. Тарифы Free и модель с суффиксом `:free` имеют квоты и не являются обещанием бессрочной бесплатности. Перед загрузкой конфиденциальных материалов проверьте политики провайдеров.

Для публичного сервиса нужны авторизация, квоты по аккаунтам и защита API-бюджета. Встроенный грубый rate limiter: 20 операций в минуту на сессию, 120 на процесс; новые cookie позволяют обходить индивидуальный лимит. Импорт сериализован глобально, ответы и изменения базы сериализуются по сессии. Приложение рассчитано на один worker, горизонтальное масштабирование требует распределённых ограничителей и блокировок.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| KIRO_API_KEY | Ключ Kiro, обязательно |
| SESSION_SECRET | Случайный секрет не короче 32 символов, обязательно |
| CHAT_BASE_URL | `https://api.xkiro.com/v1` |
| CHAT_MODEL | `qwen/qwen3.8-omni-flash:free` |
| CHAT_RESPONSE_FORMAT | `prompt` по умолчанию; `json_object`/`json_schema` только при поддержке провайдером |
| QDRANT_URL | Адрес локальной или облачной Qdrant |
| QDRANT_API_KEY | Ключ облачной Qdrant |
| QDRANT_COLLECTION | `documents_bm25_v1` |
| MIN_RELEVANCE_SCORE | 0 по умолчанию, порог BM25 score |
| BM25_K1 / BM25_B / BM25_AVG_LENGTH | 1.2 / 0.75 / 220, параметры частот и длины |
| MAX_UPLOAD_MB / MAX_PDF_PAGES | 5 / 100, ограничения обработки |
| COOKIE_SECURE | `true` для Render HTTPS, `false` локально |
| PORT | Порт HTTP; 10000 на Render, 8000 локально без переменной |

CHAT_RESPONSE_FORMAT=prompt не требует OpenAI-specific JSON Schema API. Модель получает схему в системном сообщении, JSON строго проверяется кодом. Для совместимости поддерживается OPENAI_BASE_URL, но CHAT_BASE_URL имеет приоритет. Старый OPENAI_API_KEY не отправляется на api.xkiro.com, нужен KIRO_API_KEY.

## API и тесты

Документация `/api/docs`. Все изменяющие запросы требуют `X-Requested-With: DocumentRAG`. Для CLI сохраняйте cookie между вызовами.

| Метод | Путь | Операция |
| --- | --- | --- |
| GET / HEAD | `/` | Интерфейс / проверка доступности |
| GET | `/health` | Готовность процесса |
| GET | `/api/status` | Настройки, лимиты, режим BM25 |
| GET | `/api/documents` | Документы своей сессии |
| POST | `/api/documents/upload` | Multipart поле `file` |
| POST | `/api/documents/url` | JSON `{"url":"https://example.org"}` |
| POST | `/api/chat` | JSON `{"question":"Какой срок оплаты?"}` |
| DELETE | `/api/documents/{document_id}` | Удаление документа своей сессии |
| DELETE | `/api/documents` | Очистка своей базы |

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
node --check app/static/app.js
```

Тесты охватывают PDF/TXT, чанки, точные цитаты, отказы, API Kiro, безопасность URL, sparse-векторы и нормализацию BM25, подпись cookie, изоляцию сессий, очистку, лимиты HTTP и PORT Docker. GitHub Actions дополнительно поднимает настоящую Qdrant и проверяет sparse-запись, поиск и изоляцию удаления, затем собирает образ. Реальные запросы Kiro требуют пользовательского ключа и в unit-тестах не выполняются. Интеграционный тест Qdrant пропускается без QDRANT_TEST_URL.

Для ручного теста загрузите TXT «Срок оплаты по договору составляет десять рабочих дней.», спросите «Какой срок оплаты по договору?» и проверьте цитату. Вопрос «Какой курс доллара сегодня?» должен дать отказ. Другой браузер должен увидеть пустую базу. Если возникает ошибка, проверьте Render Logs и указанный HTTP-статус; при миграции сначала проверьте имя коллекции.
