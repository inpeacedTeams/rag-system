# Архитектура

[← README](../README.md) · [Деплой](DEPLOYMENT.md) · [API](API.md)

**Источник** разделяет поиск и генерацию: Qdrant находит текстовые фрагменты, Kiro формулирует ответ, а backend проверяет связь ответа с источниками. Текущий retrieval является лексическим BM25, не семантическим нейросетевым поиском.

## Общая схема

````mermaid

    CHUNKS --> BM25["BM25 sparse-векторы"]

    QUERY --> Q
    Q --> CONTEXT["До 8 фрагментов"]
````

## Индексация документа

````mermaid
sequenceDiagram
    actor User as Пользователь
    participant API as FastAPI
    participant Parser as Извлечение текста
    participant Encoder as BM25
    participant DB as Qdrant
    User->>API: PDF / TXT / URL
    API->>API: Проверка сессии, размера и лимитов
    API->>API: Захват единственного слота импорта
    API->>Parser: Чтение файла или публичной страницы
    Parser-->>API: Чанки с текстом, страницей и номером
    API->>Encoder: Нормализация и частотные веса
    Encoder-->>API: indices + values
    API->>DB: Upsert всех чанков, wait=true
    DB-->>API: Подтверждение записи
    API-->>User: Документ готов к вопросам
````

PDF обрабатывается постранично, поэтому чанк не смешивает страницы. TXT должен быть в UTF-8. HTML очищается от скриптов и служебных элементов, содержимое страницы не исполняется.

Размер чанка составляет до 1400 символов, перекрытие до 220. Пустые фрагменты и фрагменты без поисковых терминов отбрасываются. Сохраняются текст, имя, document_id, workspace, тип источника, дата, страница, номер и URL при наличии. Исходный бинарный файл не сохраняется.

## Как устроен BM25

`app/embeddings.py` использует только стандартную библиотеку Python. Здесь нет загрузки весов или вычисления нейросетевого вектора.

Текст разбивается на слова и числа, приводится к нижнему регистру, «ё» заменяется на «е». Стоп-слова удаляются. Русские окончания нормализуются простыми правилами, английский plural частично нормализуется. Это не полноценная лемматизация и не механизм поиска синонимов.

Терм преобразуется в стабильный 32-битный ID через BLAKE2b. Для документа вычисляется частотный вес с насыщением и нормализацией длины; запрос использует единичные веса уникальных терминов. Qdrant применяет IDF при поиске. Средняя длина фиксирована настройкой BM25_AVG_LENGTH, а не вычисляется по всему корпусу, поэтому это BM25-вариант с приближённой нормализацией.

Редкие hash-коллизии возможны. IDF учитывает всю коллекцию, а фильтрация результатов производится по workspace. Другие сессии могут косвенно влиять на ранжирование через общий IDF, но их текст не возвращается текущей сессии.

````json
{
  "sparse_vectors": {
    "bm25": {
      "index": {"on_disk": true},
      "modifier": "idf"
    }
  }
}
````

Коллекция не содержит плотный cosine-вектор. Запись использует именованный вектор `bm25`, поиск задаёт `using=bm25`. Порог MIN_RELEVANCE_SCORE относится к sparse score, а не cosine similarity и не уверенности модели. После изменения параметров кодирования документы следует переиндексировать в новой коллекции.

## Ответ на вопрос

````mermaid
sequenceDiagram
    actor User as Пользователь
    participant API as FastAPI
    participant DB as Qdrant
    participant LLM as Kiro
    User->>API: Вопрос
    API->>API: Проверка сессии и sparse-вектор вопроса
    API->>DB: Поиск + фильтр workspace
    DB-->>API: До 8 фрагментов
    alt Фрагментов нет
        API-->>User: Нет подтверждённой информации
    else Фрагменты найдены
        API->>LLM: Вопрос и evidence
        LLM-->>API: found + claims с quote и source_id
        API->>API: Проверка структуры, ID и точного совпадения цитат
        alt Цитаты корректны
            API->>LLM: Проверка утверждений по цитатам
            LLM-->>API: supported
            API-->>User: Ответ с источниками или отказ
        else Подтверждения нет
            API-->>User: Нет подтверждённой информации
        end
    end
````

Пустая база и запрос без поисковых терминов обрабатываются без вызова Kiro. Модель получает только вопрос и найденные evidence, без предыдущих сообщений чата. JSON проверяется на сервере, даже если провайдер не поддерживает JSON Schema API.

Дословное совпадение цитаты проверяется детерминированно. Логическая обоснованность проверяется моделью и может быть ошибочной. Защита от prompt injection снижает риск, но не гарантирует его отсутствие. Отказ означает отсутствие подтверждения среди выбранных фрагментов, не доказанное отсутствие ответа во всей базе.

Ошибки сети, ключа, лимита провайдера, формата JSON и внутренние ошибки не подменяются обычным отказом по документам.

## Изоляция и ресурсы

Workspace определяется подписанной HttpOnly cookie, а не полем из запроса пользователя. Поиск, список и удаление фильтруются по этому workspace; payload-индексы созданы для workspace и document_id. В базе нет учётных записей пользователей.

Импорт сериализован глобальным lock: второй одновременный импорт получает 429. Чат и изменения базы сериализуются по сессии через фиксированный набор lock stripes. Rate limiter работает в памяти одного процесса. Для горизонтального масштабирования нужны внешние блокировки и ограничитель запросов.

На Render работает один контейнер приложения. Qdrant Cloud хранит индекс вне контейнера, поэтому временная файловая система Render не уничтожает коллекцию. При локальном запуске Compose поднимает отдельный Qdrant с постоянным volume.
